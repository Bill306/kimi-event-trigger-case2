Case 2 · Kimi 事件触发自动化

MVP Demo：新会议录音 → 自动纪要

一个由真实文件写入触发的完整场景，演示 Event Detection → Context Assembly → Agent Execution → Result Delivery 全链路。

Demo 聚焦一个完整场景：新增会议录音 → 自动生成会议纪要。

新的自动化待确认
“当会议文件夹出现新的录音时，自动生成会议纪要，并提取待办事项。”
监控路径
~/Documents/会议录音/
触发条件
新增 .m4a / .mp3 / .wav，写入完成后
执行动作
转写 → 摘要、关键决策、Action Items
权限范围
只读该文件夹；不联网发送；不修改原文件
交付
桌面通知 + 纪要文件 + 执行日志
确认并开始监听修改
  1. Step 1 · Configure

    用户用自然语言设置规则。Kimi 把指令转换成 Automation Card，展示监控路径、触发条件、执行动作与权限范围，用户确认后启用。

  2. Step 2 · Detect

    用户把真实录音保存到指定文件夹。Desktop Harness 通过 File System Watcher 检测到变化，等待文件写入完成，再做文件类型检查及 Hash 去重。

  3. Step 3 · Execute

    Harness 生成 Event Payload，结合 Saved Prompt 组装最小必要 Context，调用转写工具和 Agent，提取会议摘要、关键决策与 Action Items。

  4. Step 4 · Deliver

    生成结构化会议纪要，通过桌面通知提醒用户，并保存产物及 Execution Log，供后续查看和恢复。

  5. Step 5 · Validate

    除正常执行外，再验证下面三个异常场景。

Duplicate Event · 重复事件重复保存同一文件，不重复生成纪要。
Incomplete File · 文件未写完文件尚未写入完成时，不提前启动处理。
Execution Failure · 执行失败模型调用失败后有限重试；无法恢复时保留状态并通知用户。

整个 Demo 必须由真实文件写入触发，而不是点击按钮模拟事件，以验证完整链路：

Event Detection→Context Assembly→Agent Execution→Result Delivery
